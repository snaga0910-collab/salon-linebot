# 美容室向け LINE 自動応答システム

個人経営の美容室オーナー様の「**問い合わせを抱えたまま夜を過ごし、返信を忘れて翌朝謝ってしまう**」を解消するための LINE bot です。

| | |
|---|---|
| **公開URL** | https://salon-linebot-plum.vercel.app |
| 使用技術 | Next.js 16（App Router）／TypeScript／Supabase／LINE Messaging API |
| デプロイ | Vercel（無料プラン） |
| 自動テスト | **144件**（`npx vitest run`） |
| 運用コスト | **月額0円**（根拠は[下記](#運用コスト)） |

> ⚠️ これは**架空の案件**（AIエンジニア講座 案件1）の成果物です。実在の店舗ではありません。

### 画面

同じ公式アカウントのまま、**お客様とオーナーで別のリッチメニューを出します**（ユーザー単位のリッチメニュー割り当て）。どちらも2段×3列。

```
お客様                              オーナー
┌────────┬────────┬────────┐      ┌────────┬────────┬────────┐
│ 営業時間 │メニュー・料金│ 施術時間 │      │未対応の一覧│ 本日休業 │ 明日休業 │
├────────┼────────┼────────┤      ├────────┼────────┼────────┤
│ 空き状況 │ 予約の変更│その他の質問│      │日付を指定│休業を取り消す│ 使い方  │
└────────┴────────┴────────┘      └────────┴────────┴────────┘
  上段＝自動回答／下段＝人へ転送            オーナーは文字を打たずに全操作できる
```

問い合わせの通知（Flex Message）

```
※ ほかに未対応が2件あります     ← 残っていれば、いちばん上に
【至急】予約の変更             ← 急ぎのものは赤
山田 様
「明日の予約をキャンセルしたいです」
11/24 22:13 受信

［✅ 対応済みにする］          ← これを押すまで「未対応」のまま
```

> 画面の説明は [運用マニュアル](./docs/運用マニュアル.md) にもあります（オーナー様向け・専門用語なし）。

## 何をするものか

### お客様から見た動き

| 送ったこと | 返ってくるもの |
|---|---|
| 営業時間・メニュー・料金・所要時間 | **自動で即答** |
| 空き状況 | 「確認してご連絡します」と即返信し、オーナーへ通知 |
| 予約の変更・キャンセル | 同上（オーナーへは【至急】で通知） |
| クレーム・髪のお悩み | botは内容に触れず、オーナーへ転送 |

**深夜でも必ず返事が返る**ので、「既読がついたのに返事がない」がなくなります。

### オーナーから見た動き

```
夜22時　  通知が届く（［✅ 対応済みにする］ボタン付き）
　　　　　→ そのまま寝てよい

翌朝8時台 未対応のまとめが届く
　　　　　「未対応のお問い合わせが2件あります」
```

LINEから操作できるコマンド：

| 送る言葉 | 動き |
|---|---|
| `未対応` | 未対応の一覧を表示 |
| `休業 11/20は臨時休業です` | 臨時休業のお知らせを設定 |
| `休業オフ` | お知らせを取り消し |
| `ヘルプ` | コマンド一覧 |

## 設計で決めたこと

| 決めたこと | 理由 |
|---|---|
| **AIに文章を書かせない。すべて定型文** | オーナーの最優先要望が「間違った料金を伝えないこと」だったため |
| 料金は「◯◯円〜」と幅で表示 | ロング料金とセット割引があり、1つの金額で答えられないため |
| **空き状況は自動回答しない** | 予約が紙の手帳で管理されており、システムから参照できないため |
| **「対応済み」はボタンで押してもらう** | LINEは**自アカウントの送信をWebhookで受け取れない**ため、「返信したら自動で消える」は実現できない |
| リマインドは朝1回＋通知への件数同梱 | Vercel無料プランは定時実行が**1日1回まで**のため、課金せずに同じ効果を出す |
| 個人情報は最小限・30日で自動削除 | 最終的なやり取りはオーナーが直接行うため、それ以上は不要 |

## 構成

```
お客様のLINE
　　↕
LINE Messaging API
　　↕ Webhook（署名検証あり）
Next.js（Vercel）
　　↕
Supabase … 未対応の記録のみ
　　↓ プッシュ通知／毎朝8時台の定時実行
オーナーのLINE
```

| ファイル | 役割 |
|---|---|
| `src/lib/salon.ts` | **お店の正本データ**。料金・営業時間を変えるときはここだけ |
| `src/lib/classify.ts` | 問い合わせの振り分け（順番そのものが仕様） |
| `src/lib/replies.ts` | お客様への定型文 |
| `src/lib/line.ts` | 署名検証・返信・通知・Flexメッセージ |
| `src/lib/db.ts` | 未対応の記録・対応済み・自動削除 |
| `src/lib/time.ts` | 日本時間での営業時間判定 |
| `src/app/api/line/webhook/` | LINEからの受け口 |
| `src/app/api/cron/morning/` | 毎朝のまとめ通知 |

### 運用コスト

| 項目 | 月額 | 根拠 |
|---|---|---|
| LINE | **0円** | 応答メッセージは無料通数にカウントされない。プッシュは最大120通/月で無料枠200通に収まる |
| Vercel | 0円 | 無料プラン |
| Supabase | 0円 | 無料プラン |

## 開発

```bash
npm install
npm run dev
```

`.env.local` に以下を設定します（`.env.example` 参照）。

```
LINE_CHANNEL_SECRET
LINE_CHANNEL_ACCESS_TOKEN
OWNER_LINE_USER_ID
NEXT_PUBLIC_SUPABASE_URL
SUPABASE_SECRET_KEY
CRON_SECRET
```

データベースは [`supabase/schema.sql`](./supabase/schema.sql) を Supabase の SQL Editor で実行して作ります。

### テスト

```bash
npx vitest run
```

**144件**。**ヒアリングで実際に伺った文面**をそのままテストにしています。

| ファイル | 見張っているもの |
|---|---|
| `classify.test.ts` | 問い合わせの振り分け（取りこぼし） |
| `replies.test.ts` | お客様への文面（言い方・休業のお知らせの位置） |
| `salon.test.ts` | **料金・営業時間の正本**（「〜」の付け忘れ・最終受付の計算） |
| `line.test.ts` | 署名検証・Flexメッセージ |
| `closed.test.ts` | 臨時休業の日付の読み取り |

> `salon.test.ts` は、納品後にオーナー様の新しい料金表を**人の手で**書き換えるときのためのものです。
> とくに「**最終受付 ＋ 施術時間 ≦ 閉店**」は、施術時間を1つ延ばすだけで破れます。

### 本番へ出すとき

引き継ぐ人がつまずきやすい順に書きます。

```
① Vercel → Settings → Environment Variables に上の6つを登録
② LINE Developers → Messaging API → Webhook URL を
     https://＜本番URL＞/api/line/webhook  に変更し、「Webhookの利用」をON
③ LINE Official Account Manager → 設定 → 応答設定
     あいさつメッセージ → OFF
     応答メッセージ     → OFF
④ リッチメニューを登録
     python3 scripts/setup_richmenu.py
```

> ⚠️ **②を忘れると、デプロイできているのにメッセージが届きません。**
> ⚠️ **③を忘れると、あいさつが2通届きます。**管理画面の分と、このシステムの分です。
> 　　実機で一度これが起きました（[要件定義書 第12章](./docs/要件定義書.md)）。

リッチメニューの切り替え（通し確認用）

```bash
python3 scripts/setup_richmenu.py --preview-customer   # お客様側を自分で見る
python3 scripts/setup_richmenu.py --restore-owner      # オーナー側に戻す
```

### 料金・営業時間を変えるとき

`src/lib/salon.ts` **だけ**を直します。他のファイルに金額・時刻は一切書いていません。

```bash
npx vitest run src/lib/salon.test.ts
```

直したら必ずこれを走らせます。「〜」の付け忘れ、注意書きの消し忘れ、
**最終受付が閉店に間に合わない**状態は、ここで止まります。
