# テストが全部通ってから、不具合が17件見つかりました

はじめての案件で、美容室のLINE botを作りました。

自動テスト32件がすべて通った時点で、私は「できた」と思っていました。そのあと実機で触ってみたら、3件壊れていました。そこから直し続けて、最終的に**17件**になりました。

そのうち**15件は、仕様どおりに動いていました。**

壊れていたのは、実装ではなく**仕様のほう**です。この記事は、その17件がどうやって見つかったかの記録です。

---

```
依頼主  個人経営の美容室（オーナー1名・LINE友だち約320人）
依頼    LINE bot と AI自動応答

できたもの

費用    月額0円（無料枠200通に対し、最大120通/月）
```

## 1. ヒアリングで、仮説が外れた

ヒアリング前、私はこう考えていました。

> 同じ質問に繰り返し手作業で返信しているのが負担なのだろう。

全24問を3回に分けて伺った結果、**この仮説は外れました。**

| 伺ったこと | 分かったこと |
|---|---|
| 既存客が8割、新規は月2〜3人 | 料金を尋ねる人はそもそも少ない |
| 問い合わせは夜21〜23時に集中 | 返せない理由は「施術中」ではなく営業時間外 |
| 「LINEは既読がついてしまうので」 | 負担の正体は作業量ではない |

オーナー様の言葉です。

> 「買い物中にLINEが来たら『帰ってから確認してご連絡しますね』と返すんですけど、それを忘れてしまうことがあって。翌朝『すみません!!』と謝ることが月に何回かあります。」

> 「時間というより……夜、返信のことが頭から離れないのが嫌なんです。」

課題は「作業量」ではなく、**「抱えたまま夜を過ごすこと」と「返信を忘れること」**でした。

ここで責任範囲が変わりました。**一次応答を返すところで終わらせず、対応が完了するまで問い合わせを追いかける**ところまでを機能に含めました。通知を1回送るだけでは、手が離せないときに結局忘れてしまうからです。

もし仮説のまま作っていたら、FAQに答えるだけのbotを納品していたはずです。それは**動くけれど、困りごとは何も解決していない**ものになっていました。

## 2. 「AI自動応答」という依頼に、AIを使いませんでした

依頼の言葉は「LINE bot と AI自動応答」でした。それでも、**料金と営業時間の回答にAIは使っていません。**

理由は1つです。**間違った料金を答えることが、このシステムで一番やってはいけない失敗だから**です。

```
カラー　6,000円〜
※ ロングの方は +1,000円を頂戴しております
※ カットとカラーを同時にご利用の場合、お安くなります
```

この条件を、AIが毎回正しく踏まえてくれる保証はありません。**一度でも「6,000円です」と言い切れば、それは誤案内**です。お客様はその金額で来店されます。

代わりに、答えられる3種類だけを定型文で返し、**それ以外はすべて人にまわす**設計にしました。知らないことを答えないのが、このシステムで一番大事な性質です。

> 依頼の言葉どおりに作ることと、依頼の目的を満たすことは、別のことでした。

## 3. テストが全部通ったあとに、17件見つかった

ここからが本題です。見つかり方には種類がありました。

| 見つけ方 | 分かること | 件数 |
|---|---|---|
| 自動テスト | 決めたとおりに動くか | 0件 |
| **実機で触る** | **決め方そのものが間違っていないか** | **7件** |
| 書類を書く | 決めていないことがあるか | 2件 |
| 使う人の目で読み返す | 使い続けられるか | 3件 |
| 機能どうしを組み合わせる | 片方が片方を壊していないか | 2件 |
| 正本と出力を突き合わせる | 自分で決めたルールを守れているか | 2件 |
| 2つの文を並べて足し算する | 1文ずつでは正しいのに、合わせると破綻しないか | 1件 |

**自動テストで見つかった不具合は、0件です。**

テストは「決めたとおりに動くか」しか見ていません。決め方そのものが間違っているときは、テストは全部緑のまま通ります。

具体例を3つ挙げます。

### 「忘れたら困ること」を、人に覚えさせていた

臨時休業のお知らせを出す機能を作りました。当初の設計は、**オーナー様が手で取り消す**というものでした。

年5〜6回、出すたびに消す操作が必要です。消し忘れれば、**休みが終わったあとも「本日は臨時休業です」と案内し続けます。**しかも、誰も気づけません。

これに気づいたとき、自分でも言葉を失いました。**この案件の課題そのものが「返信を忘れる」だったのに、私は同じ構造の忘れ物を自分で作っていた**のです。

| | 返信忘れ | 休業の消し忘れ |
|---|---|---|
| 最初の対策 | 未対応として記録し、追いかける | **操作手順書を納品する** |
| 直したあと | 同左 | **期限で自動的に消す** |

お知らせに「終わる日」を必ず持たせ、オーナー様が何もしなくても翌日には消えるようにしました。**操作は「出す」だけで、「消す」はありません。**

### 「取りこぼさない」という約束をやめた

「髪が傷んだ」というご相談は人にまわす、と決めていました。実機で「**髪が痛みました**」と送ったところ、ただの雑談として扱われました。登録してあったのは「傷み」だけだったのです。

全カテゴリを洗い直して9件の取りこぼしを見つけ、言い方を足しました。ですが、そこで気づきました。**この作業に終わりはありません。**

```
これまで  取りこぼさないように、言い方を足していく
これから  取りこぼしても、必ず人に届くようにする
```

自動回答の末尾に必ず「そのままメッセージをお送りください」を添え、「💬 オーナーにきく」ボタンを常時出すようにしました。

| 約束 | 守れるか |
|---|---|
| 「すべての言い方を拾います」 | **守れない**（言い方は無限にあるし、誤字もある） |
| 「拾えなくても必ず人に届きます」 | **守れる**（道が1本あればよい） |

**用件を拾えないのは構いません。人に届かないのが許されないのです。**

### 1文ずつは正しいのに、足すと破綻していた

最後に見つけた17件目です。

```
「カラー・パーマは17:00が最終受付」   ← 正しい
「カット＋カラーは約120〜150分」      ← 正しい
───────────────────────────────
　　17:00 ＋ 150分 ＝ 19:30          ← 閉店19:00を過ぎる
```

**どちらの文章も、単体では間違っていません。**1文ずつ何度読み返しても、永久に見つかりません。

文章のままでは足し算できないので、**所要時間を数字で持ち直しました。**そのうえで「最終受付 ＋ 施術時間 ≦ 閉店」をテストにしました。施術時間を1つ延ばしただけで破れる約束なので、人の記憶には置けません。

> 確かめたい関係があるなら、**確かめられる形でデータを持つ**。これが対策でした。

## 4. いちばんの反省：同じ穴を3回開けた

誇れる話ではないので、正直に書きます。

同じ原因の不具合を、**3回に分けて直しました。**

| 回 | 出た症状 | 直したもの | 残っていた穴 |
|---|---|---|---|
| 1回目 | 新しい質問に「あわせてお伝えします」と返した | 問いかけの形 | ご相談・予約変更／ボタン |
| 2回目 | ご相談にも同じ返事をした | ご相談・予約変更 | ボタン |
| 3回目 | ボタンを押しても同じ返事をした | ボタン | — |

原因は最初から1つでした。「問い合わせをひとつにまとめる」のは**オーナー様側の都合**であって、**その都合をお客様への文面に出してはいけない**、というだけのことです。

ところが私は、**出てきた症状を1件ずつ**直していました。1回目の時点で「新しいご用件とみなす条件」を一覧にしていれば、1回で終わっていました。

**症状ではなく、条件を洗い出してから直す。**この案件でいちばん高くついた学びです。

## 次にやること

**「決めたとおりに動くか」と「決め方が合っているか」は、別々に確かめます。**

前者は自動テストの仕事です。後者は、実機で触る・書類に書く・使う人の目で読み返す、という**別の作業**でしか見つかりません。今回それを知らずに、テストが緑なのを見て「できた」と思っていました。

そして、見つけた関係はテストに移します。この先、料金表は人の手で何度も書き換わります。**次に同じ穴を開けるのは、自分とは限らないからです。**
