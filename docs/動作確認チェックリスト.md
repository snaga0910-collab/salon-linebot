## 使い方

1. スマホのLINEで「（テスト）サロンmina」のトークを開く
2. 上から順に「送る文面」を送る
3. 「期待する動き」と合っていれば ✅、違えば ❌ を記入する
4. ❌ があれば、**何がどう違ったか**を書き残す

> すべて ✅ になった時点を**完成**とします（要件定義書 第14章）。

## 残りの確認

### ① 残り1つ（T-24）

**先に Supabase で下の1行を実行してください。**

```sql
alter table public.sl_inquiries
  add column if not exists last_contact_at timestamptz not null default now();
```

そのうえで：

```
0.［すべて対応済みにする］で未対応を空にする
1.「空き状況を知りたいです」と送る        ← 未対応①ができる
2.「未対応」と送って一覧を出す
3. そのまま「駐車場はありますか？」と送る  ← ①への続きの連絡
4. ★2 で出した一覧の［すべて対応済みにする］を押す

　 ✅「0件」や「そのあとに届いた…」と出て、①が残れば合格
　 ❌ ①が消えたら不合格（読んでいない続きの連絡が消えたことになる）
```

> **3 は「続きの連絡」である必要があります。**
> 別人からの新規でも成立しますが、テスト用のアカウントが1つなので、
> **続きの連絡で確かめる**のがいちばん厳しい確認になります。

### ② 翌朝・翌日

T-12  朝8時台に「未対応◯件」のまとめが届く
